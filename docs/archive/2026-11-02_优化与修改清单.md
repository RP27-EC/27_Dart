## 1. 当前判断与优先级

当前工程已建立常驻任务、机构分层、通用位置轴、半自动单发、释放许可和故障登记。后续应优先完善状态可信度和机构安全边界，再接入新的外设功能。

裁判、视觉、串口屏、2.4G、测力和 TF 日志目前是桩接口；三舵机供弹有执行框架，但动作脉宽仍是占位值。不能将接口存在或软件流程完成解释为实物功能完成。

| P0 | 上机前必须解决或取得明确人工确认 | 储能状态、失联卸力、找零方式、占位参数与测试旁路 |

## 2. P0：机构安全与状态可信度

### P0-01 补齐储能状态的失效与重新确认规则

- **代码位置：**`Application/ControlLayer/dart_fsm.c`，`Fsm_Manual_Trigger_Toggle()`、`Fsm_Manual_Input()`、`Fsm_Start_Check()`、`Fsm_Step_Enter()`、`Fsm_Shot_Run()`。
- **源码事实：**人工请求释放后立即写入 `ENERGY_RELEASED`；人工锁止和上膛点动没有对应的储能重新确认逻辑。自动流程在 `SHOT_LOCK` 完成后才写入 `ENERGY_STORED`，而 `SHOT_LOAD_PREP` 会请求释放。
- **可能影响：**人工操作或流程中止后，软件对储能的判断可能落后于真实机构。如果人工动作重新形成储能，旧的 `ENERGY_RELEASED` 标志可能使启动检查放行；实际危险路径需结合锁扣结构确认。
- **建议修改：**明确哪些动作会使储能判断失效；无法证明已卸能时置为 `UNKNOWN`。区分发射释放与人工卸力，两者分别定义许可和记录。中止现场被丢弃时不能顺带假定机构已经卸能。
- **验收要求：**静态列清“上电未知、下拉中止、锁止中止、人工锁止、人工点动、失联恢复”的状态处理；人工确认未知或可能储能时不会因重新启动而非预期释放。
- **需补充信息：**真实锁扣动作、卸力方法，以及允许人工操作的机构阶段。
- [x] 完成规则确认及对应修改。（V0.2，保守规则）

### P0-02 明确 SAFE、失联和故障下的卸力策略

- **代码位置：**`dart_fsm.c` 的 `Fsm_Mode_Change()`；`Application/ControlLayer/dart_app.c` 的 `Dart_App_Control_Step()`；`Application/ModuleLayer/mech_axis.c` 的故障处理。
- **源码事实：**SAFE 关闭输出许可，发送前清零全部电机指令；舵机维持当前脉宽。上膛轴部分故障会保持位置，但 SAFE 的统一清零仍会覆盖电机输出。
- **可能影响：**下拉途中未机械锁止时，清零拉力可能导致滑台回弹。保持输出也不等于已安全卸能，不能单靠软件保持替代机构方案。
- **建议修改：**与机械共同确定正常停止、下拉中止、遥控失联、电机失联、人工卸力的处理方式，再落实模式与故障策略。
- **验收要求：**每个异常阶段都有明确的保持、停止或人工处理约定；文档能够解释残余储能及恢复条件。
- **需补充信息：**机械锁止是否可靠、失电行为、可接受的回弹边界和人工卸力步骤。
- [ ] 完成机械确认及对应修改。（部分处理：V0.3 受控回退与人工卸力，V0.6 单侧离线；待机械确认接住）

### P0-03 按机构分别选择找零方式

- **代码位置：**`dart_fsm.c` 的 `Fsm_Manual_Input()`；`ModuleLayer/loader.c`、`tension.c`、`yaw.c`。
- **源码事实：**同一次遥控操作会向上膛、变力和 Yaw 三轴同时请求堵转找零。变力和 Yaw 文件已有机械兼容警告。
- **建议修改：**将各轴找零方式独立配置；每一个对应的堵转电流应该还是有一些区别的
- **验收要求：**只有获准撞限位的机构执行堵转找零；人工零点对应明确的物理基准和方向。
- **需补充信息：**变力、Yaw 是否允许撞限位及其允许输出；不预设新限位开关或引脚。
- [x] 完成各轴找零方式确认及对应修改。（V0.2：三轴保留堵转，参数仿照 26，可配置人工零点）

## 3. P1：基础正确性与异常处理

### P1-01 修正累计编码器跨圈计算

- **代码位置：**`Application/HardwareLayer/RM_motor.c`，`Encoder_Sum_Cal()`。
- **明确问题：**跨圈补偿使用 `8191`，与每转 8192 count 的约定不一致。例如 `8191 → 0` 被算作 0 增量，正确增量应为 +1。
- **建议修改：**统一编码器模数与半圈判定，显式记录首帧初始化状态，避免用角度和累计值是否为零代替初始化标志。
- **验收要求：**静态人工演算正反向跨圈、零点附近往返及首帧；断线重连后的零点失效规则保持一致。硬件计数检查由人工完成。
- [x] 完成修改及静态核对。（V0.2）

### P1-02 为手动点动和保持状态补充适当保护

- **代码位置：**`Application/ModuleLayer/mech_axis.c`，`Mech_Axis_Jog()`、`Mech_Axis_Step()`。
- **源码事实：**点动进入 `HOLD`；堵转及运动超时检查在 `MOVING` 分支执行，`HOLD/ARRIVED` 分支只计算位置闭环。未找零时点动不受位置软限位限制。
- **可能影响：**手动顶住机构或目标长期追不上时，可能持续输出至限幅而未触发相应保护。
- **建议修改：**分别定义点动、正常承载保持和异常卡死的保护，限制未找零时的调试能力。阈值按轴确认，不能让统一堵转判断误伤正常承载。
- **验收要求：**人工确认正常上膛承载可保持，异常顶死可检测，未找零点动具有明确限制和退出方式。
- [x] 完成策略确认及对应修改。（V0.6，阈值待实测）

### P1-03 明确供弹中止后的恢复边界

- **代码位置：**`dart_fsm.c`，`Fsm_Try_Resume()`、`Fsm_Step_Enter()`；`ModuleLayer/feeder.c`，`Feeder_Request_Shot()`。
- **源码事实：**恢复供弹步骤时会重新请求序列，并把步骤号重置为 0。
- **可能影响：**中止前若已经放行一枚，重新执行整套序列可能重复放行；实际后果取决于最终机构。
- **建议修改：**标识放行等不可重复动作；根据机械允许性决定继续、退回或人工处理。无法确认储弹状态时禁止无条件重做。
- **验收要求：**每个供弹步骤的中止和恢复规则均有定义；没有传感器时只报告序列执行状态，不宣称已经检测到有镖、缺镖或卡镖。
- [x] 完成恢复规则及对应修改。（V0.2）

### P1-04 修正串口接收长度与 DMA 重启约定

- **代码位置：**`Application/DriverLayer/drv_uart.c`，`uart_rx_idle_callback()`；`Application/ConfigLayer/config_uart.c`。
- **源码事实：**USART1 分支已重置 DMA 接收计数，USART6 分支未做同样处理；屏幕和裁判路由传递的是缓冲容量，而不是本次实际收到的字节数。
- **可能影响：**接入实际协议后，多次接收、短帧、拆包和连续帧的处理缺少可靠边界。
- **建议修改：**明确实际有效长度、DMA 计数重装和缓冲所有权；协议层处理拆包、粘包与异常帧，中断中只执行必要接收处理。
- **验收要求：**静态核对 DMA 模式、有效长度和回调生命周期；协议接入后的实际收包验证由人工完成。
- **文档同步：**README 中“USART1/6 均未重置 DMA 计数”的描述应改正，USART1 已有对应代码。
- [x] 完成串口底层及 README 同步。（V0.2）

### P1-05 上报输出发送失败与机构请求拒绝

- **代码位置：**`HardwareLayer/RM_motor.c` 的 `Group_Motor_Set_Torque()`；`DriverLayer/drv_can.c` 的 `CAN_SendData()`；`ControlLayer/dart_fsm.c` 的手动请求入口。
- **源码事实：**CAN 底层返回发送失败，但电机组发送没有向业务层传播结果；部分手动机构请求返回值被直接忽略。
- **可能影响：**难以区分请求被拒、输出已计算、进入发送邮箱及设备实际执行。
- **建议修改：**记录发送失败与请求拒绝原因，并定义持续失败的处理；避免在控制周期中阻塞等待或无限重试。
- **验收要求：**拒绝原因可读，发送失败可追溯；不能把进入邮箱等同电调已执行。
- [ ] 完成错误传播和诊断接口。（未处理）

### P1-06 修正日志计数并发与事件语义

- **代码位置：**`Application/DeviceLayer/tf_log.c`，`Log_Event()`；`dart_fsm.c`，`Fsm_Try_Fire()`。
- **源码事实：**日志当前丢弃事件参数并恒返回 `false`；`s_drop_count++` 可由控制、监控任务调用，不符合文件注释中的“单写”假设。释放计数在请求释放时增加，没有出膛反馈。
- **建议修改：**保护共享计数或采用单一消费入口；在存储后端实现前明确日志不可持久化。区分释放命令、实际出膛、裁判出镖及命中记录。
- **验收要求：**事件记录语义准确，计数无并发丢更新；未取得对应反馈时不能生成实际出膛或命中结论。
